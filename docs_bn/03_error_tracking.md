# ३. ত্রুটি এবং ব্যতিক্রম ট্র্যাকিং

## 🎯 এই বৈশিষ্ট্যটি কি?

যেকোনো ত্রুটি বা ব্যতিক্রম ঘটলে সম্পূর্ণ বিস্তারিত স্বয়ংক্রিয়ভাবে লগ এবং সংরক্ষিত হয়।

## 🤔 কেন প্রয়োজন?

- ব্যবহারকারী ত্রুটির কথা বলছে কিন্তু আপনি দেখতে পাচ্ছেন না
- একই ত্রুটি বারবার হচ্ছে - কতবার?
- কোন ত্রুটি সবচেয়ে সাধারণ
- ত্রুটি কোথায় ঘটছে (কোন ফাইল এবং লাইন)
- ত্রুটির সম্পূর্ণ প্রসঙ্গ দেখুন

## 📝 কি তথ্য সংরক্ষিত হয়?

প্রতিটি ত্রুটির জন্য:

| ডেটা | বর্ণনা | উদাহরণ |
|------|-------|---------|
| **বার্তা** | ত্রুটি বার্তা | "SQLSTATE[HY000]: General error" |
| **ক্লাস** | ব্যতিক্রম ধরন | Exception, RuntimeException |
| **ফাইল** | ত্রুটির অবস্থান | app/Models/User.php |
| **লাইন** | লাইন সংখ্যা | ४२ |
| **স্ট্যাক ট্রেস** | সম্পূর্ণ কল স্ট্যাক | ত্রুটি কোথা থেকে এসেছে তা ট্র্যাক করুন |
| **গণনা** | এই ত্রুটি কতবার | २४ বার |

## 🔧 কনফিগারেশন

### ত্রুটি ট্র্যাকিং চালু/বন্ধ করুন

```php
// config/request-log-analyzer.php
'track_errors' => env('REQUEST_LOG_ANALYZER_TRACK_ERRORS', true),
```

`.env` ফাইলে:

```env
REQUEST_LOG_ANALYZER_TRACK_ERRORS=true
```

### সর্বদা ত্রুটি ক্যাপচার করুন

নমুনা হার সত্ত্বেও সমস্ত ত্রুটি ক্যাপচার করুন:

```php
'always_capture_errors' => env('REQUEST_LOG_ANALYZER_CAPTURE_ERRORS', true),
```

এটি নিশ্চিত করে যে কোনো ত্রুটি মিস হবে না, এমনকি যদি নমুনা হার ১০% হয়।

### উপেক্ষা করার প্যাটার্ন

নির্দিষ্ট ত্রুটি উপেক্ষা করুন:

```php
'ignore_exceptions' => [
    'HttpNotFoundException',
    'ModelNotFoundException',
],
```

## 📊 ত্রুটি দেখুন এবং বিশ্লেষণ করুন

### সমস্ত ত্রুটির তালিকা

ড্যাশবোর্ডে যান:

```
/request-log-analyzer
```

"সর্বশেষ ত্রুটি" বিভাগ দেখুন। এখানে দেখবেন:

✅ সবচেয়ে সাম্প্রতিক ত্রুটি  
✅ কতবার ঘটেছে  
✅ শেষে কখন ঘটেছে  

### ত্রুটির বিস্তারিত

যেকোনো ত্রুটিতে ক্লিক করলে পাবেন:

- **সম্পূর্ণ ত্রুটি বার্তা**
- **ব্যতিক্রম ধরন**
- **ত্রুটি ফাইল এবং লাইন**
- **স্ট্যাক ট্রেস** - কল ট্র্যাক করুন
- **যে রিকোয়েস্টে এটি ঘটেছে** - মেথড, URL, ব্যবহারকারী
- **ডাটাবেস কোয়েরি** যা ত্রুটির আগে চলেছিল

### ত্রুটি নিদর্শন খুঁজুন

একই ত্রুটি বার বার হচ্ছে?

```
/request-log-analyzer
```

"শীর্ষ ত্রুটি" চার্ট দেখুন - সবচেয়ে সাধারণ ত্রুটিগুলি প্রথমে দেখা যায়।

## 🔍 সমস্যা সমাধান

### ত্রুটির উৎস খুঁজুন

**স্টেপ ১**: স্ট্যাক ট্রেস পড়ুন
- সর্বনিচে শুরু করুন এবং উপরে যান
- প্রথম লাইন যা আপনার কোডে আছে তা খুঁজুন

**স্টেপ २**: সেই ফাইল খুলুন
- যে লাইন নম্বর দেখানো হয়েছে সেখানে যান
- সেই লাইন এবং তার পরে কোডটি বুঝুন

**স্টেপ ३**: ভেরিয়েবল চেক করুন
- রিকোয়েস্ট ডেটা কি ঠিক?
- ডাটাবেস রেকর্ড বিদ্যমান?
- অনুমতি সঠিক?

### সাধারণ ত্রুটি এবং সমাধান

**১. "SQLSTATE[HY000]: General error"**
- এটি সাধারণত ডাটাবেস সংযোগ সমস্যা
- সমাধান: ডাটাবেস ক্রেডেনশিয়াল চেক করুন

**२. "Method not found"**
- আপনি এমন কিছু কল করছেন যা নেই
- সমাধান: অবজেক্টের ধরন চেক করুন

**३. "Undefined index"**
- অ্যারেতে সেই কী নেই
- সমাধান: কী বিদ্যমান আছে কি না চেক করুন

## 🚨 সতর্কতা এবং বিজ্ঞপ্তি

### ত্রুটির জন্য সতর্কতা সেট করুন

ইমেইল পান যখন:

```php
// config/request-log-analyzer.php
'alert_on_errors' => true,
'error_alert_threshold' => 10,  // ১০টি ত্রুটির পর সতর্কতা
'alert_email' => env('ALERT_EMAIL', 'admin@example.com'),
```

## 💾 ডাটাবেস টেবিল

সমস্ত ত্রুটি এখানে সংরক্ষিত হয়:

```
rla_errors
```

## 📈 ত্রুটি রিপোর্ট

### সাপ্তাহিক রিপোর্ট

আপনার ত্রুটি প্রবণতা দেখুন:

```
/request-log-analyzer/analytics
```

এখানে পাবেন:
- এই সপ্তাহে কত ত্রুটি
- গত সপ্তাহের সাথে তুলনা
- সবচেয়ে সাধারণ ত্রুটি টাইপ

### ত্রুটি গ্রুপিং

একই ত্রুটি একসাথে গ্রুপ করা হয়:
- একই বার্তা
- একই ফাইল এবং লাইন
- স্বয়ংক্রিয়ভাবে ঐতিহ্যগত হয়

२. **যত তাড়াতাড়ি ঠিক করুন** - নতুন ত্রুটি প্রথম দিনই ঠিক করুন
